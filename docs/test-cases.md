# Тест-кейсы – API Automation Test
## TК-01: Создание сущности (POST /entity)
### Предусловия
- Сервис запущен
- База данных доступна
### Шаги
1. Отправить POST `/entity` с телом:
```json
{
  "title": "Заголовок сущности 1",
  "verified": true,
  "important_numbers": [42, 87, 15],
  "addition": {
    "additional_info": "Дополнительные сведения 1",
    "additional_number": 123
  }
}
```
2. Получить entityId из ответа
3. Отправить GET `/entity/{id}`
### Ожидаемый результат
1. Статус-код ответа = 200
2. entityId не null и > 0
3. GET возвращает созданную сущность
4. Все поля совпадают с отправленными данными

## TК-02: Получение сущности по ID (GET /entity/{id})
### Предусловия
- Сервис запущен
- База данных доступна
- Существует созданная сущность (через POST)
### Шаги
1. Создать сущность через POST `/entity`
2. Получить `entityId` из ответа
3. Отправить GET `/entity/{entityId}`
### Ожидаемый результат
- Статус-код ответа = 200
- В ответе возвращается сущность
- Поле `id` совпадает с `entityId`
- Все поля совпадают с созданными данными:
    - title
    - verified
    - important_numbers
    - addition.additional_info
    - addition.additional_number

## TК-03: Получение всех сущностей (GET /entities)
### Предусловия
- API сервис запущен
- База данных доступна
- Существуют минимум 2 созданные сущности (через POST)
### Шаги
1. Создать первую сущность через POST `/entity`
2. Создать вторую сущность через POST `/entity`
3. Отправить GET запрос `/entities?page=1&perPage=100`
### Ожидаемый результат
- Статус-код ответа = 200
- Ответ содержит список сущностей
- Список не пустой
- В списке присутствуют созданные сущности
- Проверка по `id`:
    - id первой сущности присутствует в ответе
    - id второй сущности присутствует в ответе

## TК-04: Обновление сущности (PATCH /entity/{id})
### Предусловия
- Сервис запущен
- База данных доступна
- Существует созданная сущность (через POST)
### Шаги
1. Создать сущность через POST `/entity`
2. Получить `entityId` из ответа
3. Отправить PATCH запрос `/entity/{entityId}`
4. Тело запроса (обновлённые данные):
```json id="patch_body"
{
  "title": "Заголовок сущности 2",
  "verified": true,
  "important_numbers": [42, 87, 15],
  "addition": {
    "additional_info": "Дополнительные сведения 1",
    "additional_number": 123
  }
}
```
5. Отправить GET запрос `/entity/{entityId}`
### Ожидаемый результат
- Статус-код ответа = 204
- Данные сущности обновлены
- GET возвращает обновлённую сущность
- Проверка полей:
    - title обновился
    - verified совпадает
    - important_numbers совпадает
    - addition.additional_info совпадает
    - addition.additional_number совпадает

## TК-05: Удаление сущности (DELETE /entity/{id})
### Предусловия
- Сервис запущен
- База данных доступна
- Существует созданная сущность (через POST)
### Шаги
1. Создать сущность через POST `/entity`
2. Получить `entityId` из ответа
3. Отправить DELETE запрос `/entity/{entityId}`
4. Попробовать получить удалённую сущность GET `/entity/{entityId}`
### Ожидаемый результат
- Статус-код ответа = 204
- Сущность удалена из системы
- GET после удаления возвращает ошибку 400 или 404 (в зависимости от реализации API)
- Сущность больше не доступна
